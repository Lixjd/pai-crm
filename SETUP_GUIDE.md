# Гайд по установке и запуску — с нуля до рабочего бота

Это пошаговая инструкция для тех, кто раньше не разворачивал Python-проекты.
Идём по порядку, ничего не пропускаем.

---

## Часть 1. Получаем токен Discord-бота

1. Открой https://discord.com/developers/applications
2. **New Application** → дай название (например `PAI CRM`) → Create.
3. Слева открой **Bot** → **Reset Token** (или **Add Bot**, если это первый раз) → **Copy**.
   Это и есть `DISCORD_TOKEN`. **Никому его не показывай и не выкладывай в открытый доступ** —
   с ним можно полностью управлять ботом.
4. На этой же странице **Bot** включи переключатель **Server Members Intent**
   (он нужен, чтобы бот видел участников сервера и их роли). Сохрани.
5. Слева открой **OAuth2 → URL Generator**:
   - В **Scopes** отметь `bot` и `applications.commands`.
   - В **Bot Permissions** отметь как минимум: `Send Messages`, `Embed Links`,
     `Read Message History`, `Use Slash Commands`.
   - Внизу скопируй сгенерированную ссылку, открой её в браузере и выбери свой сервер —
     бот появится в списке участников (пока офлайн, это нормально).
6. Узнай **ID сервера** (`DISCORD_GUILD_ID`): в Discord включи Настройки → Расширенные →
   **Режим разработчика**, затем правой кнопкой по иконке сервера → **Копировать ID сервера**.
7. Узнай **ID ролей** для `ADMIN_ROLE_IDS` (кому разрешены админ-команды): правой кнопкой
   по нужной роли в списке ролей сервера → **Копировать ID роли**. Можно указать несколько
   через запятую.

## Часть 2. Устанавливаем Python и зависимости

Нужен **Python 3.10 или новее**. Проверить версию:

```bash
python3 --version
```

Если Python не установлен — скачай с https://www.python.org/downloads/ (при установке
на Windows обязательно поставь галочку **Add Python to PATH**).

Дальше, находясь в папке с распакованным проектом (`pai-crm`):

```bash
cd pai-crm
python3 -m venv venv               # создать изолированное окружение
source venv/bin/activate           # Windows (PowerShell): venv\Scripts\Activate.ps1
pip install -r requirements.txt    # поставить все библиотеки
```

## Часть 3. Настраиваем .env

```bash
cp .env.example .env
```

Открой `.env` любым текстовым редактором и заполни:

```
DISCORD_TOKEN=токен_из_части_1_шаг_3
DISCORD_GUILD_ID=id_сервера_из_части_1_шаг_6
ADMIN_ROLE_IDS=id_роли_1,id_роли_2
DATABASE_URL=sqlite+aiosqlite:///./pai_crm.db      # можно не трогать
WEB_ADMIN_PASSWORD=придумай_свой_пароль
WEB_SECRET_KEY=любая_случайная_строка_подлиннее
```

**`.env` никогда не должен попадать в GitHub** — там лежит токен бота. Это уже учтено
в `.gitignore` (см. часть 5).

## Часть 4. Запуск

Два процесса — бот и веб-панель — независимы и запускаются отдельно (в двух окнах терминала).
Оба должны быть активны, чтобы бот и панель работали одновременно; они делят одну и ту же
базу данных, поэтому изменения в одном месте сразу видны в другом.

Терминал 1 — бот:
```bash
source venv/bin/activate
python -m bot.bot
```
Если всё верно, в консоли появится `Бот запущен как PAI CRM#0000`, а в самом Discord бот
станет "онлайн". Slash-команды (`/состав`, `/отчёт` и т.д.) появятся в течение минуты.

Терминал 2 — веб-панель:
```bash
source venv/bin/activate
python -m web.main
```
Открой в браузере http://localhost:8000 и войди с паролем `WEB_ADMIN_PASSWORD`.

При первом запуске любого из двух процессов автоматически создастся файл `pai_crm.db`
(база данных) — вручную ничего накатывать не нужно.

## Часть 5. Заливаем на GitHub

Если у тебя ещё нет аккаунта — зарегистрируйся на https://github.com, затем создай
пустой репозиторий (**New repository**, без README/gitignore — они уже есть в проекте,
либо просто не отмечай "Initialize with README").

В папке проекта:

```bash
cd pai-crm
git init
git add .
git commit -m "Первый коммит: PAI CRM"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/НАЗВАНИЕ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

Прежде чем коммитить, создай файл `.gitignore` в корне проекта (если его ещё нет)
со следующим содержимым — это защитит токен и лишние файлы от попадания в GitHub:

```
.env
venv/
__pycache__/
*.pyc
pai_crm.db
```

Дальше, после любых правок:
```bash
git add .
git commit -m "Описание изменений"
git push
```

На новой машине (например, на сервере) — просто:
```bash
git clone https://github.com/ТВОЙ_ЛОГИН/НАЗВАНИЕ_РЕПОЗИТОРИЯ.git
cd НАЗВАНИЕ_РЕПОЗИТОРИЯ
# .env туда не попадёт (он в .gitignore) — создай его заново тем же способом (часть 3)
```

## Часть 6. Чтобы бот работал круглосуточно (не только пока открыт твой компьютер)

На своём компьютере бот работает, только пока запущен терминал. Для постоянной работы
нужен сервер (VPS) или облачный хостинг. Варианты, от простого к гибкому:

- **Railway** (`railway.app`) или **Render** (`render.com`) — подключаешь GitHub-репозиторий,
  задаёшь переменные окружения (те же, что в `.env`) через их веб-интерфейс, они сами
  ставят зависимости и запускают процесс. Проще всего для старта, есть бесплатные лимиты.
- **VPS** (например, Timeweb, Selectel, Hetzner) — арендуешь сервер на Ubuntu, заходишь по SSH,
  повторяешь части 2–4, а чтобы процессы не останавливались при закрытии SSH-сессии — запускаешь
  их через `systemd` (создать `.service`-файл для бота и для панели) или через `tmux`/`screen`.

Если решишь разворачивать на конкретном сервисе — скажи, какой выбрал, и я распишу
шаги именно под него (у каждого своя специфика переменных окружения и портов).

## Частые проблемы

| Проблема | Причина |
|---|---|
| Бот не отвечает на команды | Не прошла синхронизация — подожди 1–2 минуты после первого запуска, или проверь `DISCORD_GUILD_ID` |
| `401 Unauthorized` в панели | Неверный `WEB_ADMIN_PASSWORD` в `.env`, либо истекла сессия — войди заново |
| `discord.errors.LoginFailure` | Неверный `DISCORD_TOKEN`, либо он был сброшен в Developer Portal — сгенерируй новый |
| Команды без прав пишут "нет доступа" | Роль пользователя не входит в `ADMIN_ROLE_IDS` |
| Панель и бот показывают разные данные | Запущены с разными `.env` / `DATABASE_URL` — должен использоваться один и тот же файл базы |
