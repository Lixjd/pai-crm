# PAI CRM — Discord-бот + веб-панель отдела

Система управления отделом **PAI**: состав, еженедельные отчёты с баллами,
сводка активности, выговоры, дневная норма и события с отметкой присутствия.
Бот и веб-панель работают с **одной и той же базой данных**, поэтому
изменения видны сразу в обоих местах.

## Требования

- Python **3.10+**
- Токен Discord-бота (создаётся в https://discord.com/developers/applications)

## Установка

```bash
cd pai-crm
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и заполните:

- `DISCORD_TOKEN` — токен бота
- `DISCORD_GUILD_ID` — ID вашего Discord-сервера (для мгновенной синхронизации команд)
- `ADMIN_ROLE_IDS` — ID ролей, которым разрешены админ-команды (состав, баллы, выговоры), через запятую. Если оставить пустым — админ-командами временно смогут пользоваться все (не рекомендуется для боевого сервера)
- `WEB_ADMIN_PASSWORD` — пароль для входа в веб-панель
- `WEB_SECRET_KEY` — любая случайная строка (для подписи сессий)

При первом запуске (бота или веб-панели) файл базы данных `pai_crm.db`
и все таблицы создаются автоматически — ничего вручную накатывать не нужно.

## Права бота в Discord

При создании приглашения боту нужны intents:
- `applications.commands`
- `bot`

Права: минимум "Отправка сообщений", "Использовать embed-ссылки", "Читать историю сообщений".
В настройках приложения в Discord Developer Portal включите **Server Members Intent**.

## Запуск бота

```bash
python -m bot.bot
```

## Запуск веб-панели

```bash
python -m web.main
```

По умолчанию панель поднимется на `http://localhost:8000`. Откройте её в браузере
и войдите с паролем из `WEB_ADMIN_PASSWORD`.

Оба процесса можно (и нужно) запускать одновременно — они независимы и
общаются только через файл базы данных.

## Что где находится

```
pai-crm/
├── core/               # общая логика: модели БД, доступ к данным (используется и ботом, и панелью)
│   ├── models.py        # структура БД (сотрудники, отчёты, баллы, выговоры, норма, события)
│   ├── crud.py           # вся бизнес-логика (добавление, подсчёт баллов, сводки и т.д.)
│   ├── database.py
│   └── config.py
├── bot/                 # Discord-бот
│   ├── bot.py            # точка входа
│   └── cogs/             # слэш-команды по разделам
│       ├── roster.py           # /состав добавить|удалить|изменить|список
│       ├── points_settings.py  # /баллы-настройка добавить|изменить|удалить|список
│       ├── reports.py          # /отчёт сдать|сводка
│       ├── warnings.py         # /выговор выдать|история|снять
│       ├── norms.py            # /норма отметить|таблица
│       └── events.py           # /событие создать|список|отметить|посещаемость
└── web/                 # Веб-панель (FastAPI + REST API)
    ├── main.py
    └── static/            # дашборд (HTML/CSS/JS, без сборки)
```

## Основные команды бота

| Команда | Что делает |
|---|---|
| `/состав добавить` | добавить сотрудника (имя, фамилия, static, должность) |
| `/состав список` | показать весь состав по должностям |
| `/баллы-настройка добавить` | задать вид работы и баллы за него |
| `/отчёт сдать` | сотрудник сдаёт еженедельный отчёт, баллы считаются автоматически |
| `/отчёт сводка` | кто сдал/не сдал отчёт за неделю и сколько баллов набрал |
| `/выговор выдать` | выдать 1 варн / 2 варна / понижение |
| `/норма отметить` | отметить холл-час и гос. волну за сегодня |
| `/норма таблица` | таблица выполнения нормы за N дней |
| `/событие создать` | создать собрание, автоматически пригласить весь состав |
| `/событие отметить` | отметить присутствие/отсутствие на собрании |

## Дальнейшие доработки (если понадобятся)

Всё уже спроектировано так, чтобы это было легко добавить:
- Автоматические авто-уведомления в канал, если отчёт не сдан к дедлайну
- Автоматическая логика "2 варна → понижение" (сейчас уровень выбирается вручную)
- Роли/права по уровням доступа в самой веб-панели (сейчас один общий пароль)
- Экспорт отчётов/сводок в Excel

Дай знать, если что-то из этого понадобится, или всплывут дополнительные требования —
структура это позволяет нарастить без переделки существующего.
